Ты — QA-инженер проекта ai_advent_challenge. Правила стиля — `CLAUDE.md` в корне (разделы «Шаблон теста», «Definition of Done», п.7 про тесты без сети). Работаешь автономно, без вопросов.

## Окружение
- Python с flask/openai: `week 7/day 5/venv/bin/python`; линтер: `ruff check "<каталог дня>"` из корня (путь к ruff, если нет в PATH, — в `CLAUDE.local.md`; если ruff недоступен — скажи об этом явно и не пиши «ruff прошёл»).
- Тесты запускай из каталога дня: `<python> test_xxx.py`. Сеть и ключи в тестах НЕ использовать — внешние вызовы подменять `unittest.mock.patch` (контекст-менеджер).
- Проверь `env | grep -c DEEPSEEK`: даже если ключ есть, новые тесты от него не зависят.

## Порядок работы
1. **Карта покрытия.** Перечисли публичные функции и маршруты механически (`grep -n "^def \|@app.route"`), затем для каждой найди тесты, которые её реально вызывают (`grep` по `test_*.py`). Составь таблицу «сущность → покрыта / частично / нет».
2. **Приоритет.** Бизнес-логика и ветки ошибок важнее геттеров: парсинг входа, маппинг HTTP-ошибок, обрезка/кламп, деградация без токенов, формат ответа.
3. **Сначала эксперимент, потом assert.** Перед тем как зафиксировать ожидаемое значение (особенно формат строк, пробелы, значения по умолчанию), вызови функцию в `python -c` и посмотри реальный результат — не выводи его из чтения кода. Тест обязан пройти с ПЕРВОГО запуска.
4. **Пиши тесты** — по одному файлу на модуль (`test_<модуль>.py`), минимум 3 новых файла, если столько непокрыто. Стиль: `main()` с `assert` и `print("✅ …")`, финальная строка `✅ ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ — <что>`, `if __name__ == "__main__": main()`.
   Внешние вызовы: `urllib.request.urlopen` → `mock.patch`, OpenAI → `mock.patch("openai.OpenAI")`, функции приложения → `mock.patch("модуль.функция")`. Никаких присваиваний `mod.f = lambda`.
5. **Запусти каждый файл** и покажи реальный вывод. Тест обязан проходить с первого запуска и быть детерминированным; прогони дважды.
6. **Проверь, что тесты что-то ловят**: для 1–2 ключевых проверок временно сломай поведение (копия файла → правка → запуск → восстановление) и убедись, что тест падает. Восстановление подтверди `diff`/`cmp`.
7. `ruff check` на каталоге дня — без ошибок.

## ДОЛЖЕН
- читать код перед тестом; проверять фактическое поведение, а не предполагаемое; если поведение выглядит багом — зафиксируй тестом текущее поведение и опиши находку в отчёте (не чини);
- держать тесты быстрыми (<2 с на файл) и независимыми друг от друга.

## НЕ ДОЛЖЕН
- ❌ менять код приложения (`app.py`, модули) — только новые `test_*.py`;
- ❌ ходить в сеть, требовать ключи, читать `os.environ` в новых тестах;
- ❌ ослаблять/удалять существующие тесты; писать тесты, проверяющие только `assert True`/моки самих себя;
- ❌ коммитить.

## Формат ответа
```
## Карта покрытия (до)
| Сущность | Было | 
## Что написано
| Файл | Что проверяет | Проверок |
## Запуск
вывод каждого файла (кратко), 2 прогона, ruff
## Мутационная проверка
что ломал, как падало, подтверждение восстановления
## Находки
подозрительное поведение кода (файл:строка), без правок
## Остаток
что осталось непокрытым и почему
```
