# Неделя 10, день 4 — Execution loop с security step через LLM-шлюз

Цикл «промпт → генерация → линтер/тесты → **security review** → коммит». Все вызовы LLM (и генерация, и ревью)
идут через шлюз из [../day 3](../day%203/README.md) с профилем `code` и режимом `mask`. Модель — локальная
`qwen3.5-122b`. Подключение к серверу — [../day 1/SERVER.md](../day%201/SERVER.md).

```
задача + контекст проекта ──► шлюз (Input Guard: маскирует секреты и PII) ──► модель ──► шлюз (Output Guard)
        ▲                                                                                      │
        │ «исправь: <находка> в строке N»                                                      ▼
   фидбек ◄── High/Critical ◄── security review (2-й вызов, свой промпт) ◄── ruff (E9,F) и тесты ◄── файлы
                                    │
                         Medium/Low → коммит + предупреждение в логе · чисто → коммит · ревью недоступно → без коммита
```

## Модули

| Файл | Назначение |
|---|---|
| `loop.py` | Цикл на задачу, CLI, события в `events.jsonl`, отчёт |
| `security_prompt.py` | Security-промпт с профилями `python` (Python 3.13 + Flask + SQLite — стек репозитория), `ios`, `android` |
| `review.py` | Разбор JSON ревью, политика: Critical/High → назад, Medium/Low → предупреждение, чисто → коммит |
| `codegen.py` | Промпт генерации и разбор файлов `solution.py` / `test_solution.py` из ответа |
| `sandbox.py` | Песочница: отдельный git-репозиторий, контекст с подмешанными секретами и PII, ruff, тесты, коммит |
| `gateway_client.py` | Клиент шлюза (маскирование, ответы guard'ов, повтор при 429) |
| `gateway_launcher.py` | Запуск шлюза из day 3 с журналом в `runs/gateway/` этого дня |
| `report.py` | Отчёт и проверка «дошло ли до модели» по журналу самого шлюза |
| `tasks.py` | Три задачи; `test_loop.py` — тесты цикла без сети (подмена шлюза) |
| `runs/` | Артефакты всех прогонов (события, отчёты, код модели, журналы шлюза) |

## Запуск

```bash
# 1) шлюз (интерпретатором venv из day 3), порт 5013; журнал — в runs/gateway/
export LLAMA_API_KEY=...  LLAMA_BASE_URL=http://<адрес>:8080/v1
"../day 3/venv/bin/python" gateway_launcher.py &

# 2) цикл
python3.13 loop.py --python python3.13 --ruff <путь к ruff> [--tasks T1,T2,T3] [--max-iter 4] [--stack python|ios|android]

# тесты цикла (без сети)
python3.13 test_loop.py
```

Результат: `runs/<время>/report.md`, `events.jsonl` (каждый вызов шлюза: решение по входу и выходу, токены,
стоимость; тела промптов и секретов в логе нет), `results.json`, `T*/solution.py`, `T*/test_solution.py`.

## Что подмешано в контекст (чтобы проверить шлюз)

Песочница содержит `config.py` (ключ в формате OpenAI, `DB_PASSWORD`, email), `sample_users.csv` (email,
телефоны, номера карт). Эти файлы уходят в промпт каждой генерации. В задачу T3 ключ вписан текстом, как это
делают пользователи. Тестовые значения собираются в коде на лету, в исходниках готовых ключей нет.

### Что поймал шлюз

- **Все 8 подмешанных значений не дошли до модели** (по журналу самого шлюза, `runs/gateway_run5/audit.jsonl`
  и `runs/gateway_run4/`): ключ (в `config.py` и в тексте задачи T3), `DB_PASSWORD`, 2 email, 2 телефона, 2 карты.
- Входящие находки: `api_key`, `secret_assignment`, `email`, `phone`, `card`. Режим `mask` позволил циклу работать
  дальше: модель видела `[REDACTED_API_KEY]` и т. п.
- **Первая версия не поймала `DB_PASSWORD = "…"`** (`gateway_run1`): имя с префиксом и значение в кавычках не
  попадали в шаблон. Исправлено в day 3, после этого перехватывается.
- **Выход:** 2–4 раза за прогон Output Guard маскировал `secret_assignment` в сгенерированном коде. В двух прогонах
  это было ложное срабатывание, которое ломало код (`run1`, `run4`); исправлено в day 3. Оставшиеся маскировки
  касаются строковых литералов с «секретами» в тестах (`token = "…"`), код остаётся валидным.
- Блокировок по входу и выходу в итоговых прогонах не было: контекст маскируется, а не отклоняется.

### Что поймал security review

- **Ветка «Critical/High → назад на генерацию» сработала вживую (T1).** В первой версии ревью поставило High:
  токен хранится в открытом виде и гонка условий (файл создаётся раньше, чем выставляются права). Модель
  переписала код. Поскольку я разрешил в промпте генерации только стандартную библиотеку, она придумала
  собственное «шифрование» (XOR + PBKDF2); ревью поставило Critical («XOR-шифрование не защищает»,
  «захардкоженный запасной ключ») и поймало, что комментарий «XOR из-за ограничения stdlib» оправдывает небезопасное
  решение. После 4 итераций цикл **не закоммитил ничего**: небезопасный код не попал в репозиторий.
- **Medium/Low пропускаются с предупреждением** (T2, T3): так и задумано, предупреждения лежат в `events.jsonl`
  (`event: "warning"`).
- Если ревью недоступно или ответ нельзя разобрать, коммита нет (fail closed): так закончились `run2` и `run3`.

### Что прошло мимо обоих (моя ручная оценка по коду)

**T2 (закоммичен).** Логирование всех запросов, и вот что в нём осталось:
- Маскируются только заголовки по точному имени и **верхний уровень** JSON-тела. Вложенные объекты
  (`{"user": {"password": "…"}}`) пишутся как есть. Тело не-JSON (форма `password=…`) пишется в лог целиком.
- PII в значениях тела (email, телефон, номер карты) не маскируется вообще: маскируются только ключи из списка.
- URL пишется как есть, а секреты нередко лежат в query (`?api_key=…`).
- `urlopen` без проверки схемы (`file://`, SSRF); это нашёл только независимый сканер ruff (правило S310), ревью — нет.
- Ревью нашло «шум» (ошибки декодирования), но не эти утечки, которые гораздо важнее.

**T3 (закоммичен).** Код берёт ключ из `config.py` (`from config import API_KEY`) и сам ничего не хардкодит, но ключ
по-прежнему лежит открытым текстом в `config.py`. Ревью и шлюз смотрят только на `solution.py`, поэтому
**исходная проблема (секрет в репозитории) осталась**. Ревью справедливо отметило отсутствие таймаута, но как Medium.

**Занижение серьёзности.** В `run3` в T2 была функция, которая «маскировала» тело запроса через
`body.replace("password", "[REDACTED]")`: она заменяла **имя поля**, а значение пароля оставалось в логе.
Ревью эту ошибку увидело, но поставило **Medium**, хотя по шкале из его же промпта это High; политика
«блокируют только Critical/High» пропустила реальную утечку. См. `runs/run3_t3_review_empty/T2/solution.py`.

**Ложная зелёная проверка.** В `run5` (итерация 4) тесты завершились с кодом 0, хотя в их выводе есть traceback
из `save_token` (вызов `hashlib.pbkdf2_hmac(..., info=...)` с несуществующим аргументом). Цикл доверяет коду
возврата, а тесты модели могут глотать исключения.

## Что не доказано / ограничения

- По одному запуску на задачу, температура 0,2; модель недетерминирована. Результаты 2–3 прогонов одной и той же
  задачи различались (например, T1 в `run3` закоммитилась с Medium, а в `run5` была отклонена).
- Оценку «что прошло мимо» делал я вручную, читая код; независимый сканер (ruff S) нашёл только S310. Это не аудит.
- Мои ограничения подтолкнули модель к плохому решению: требование «только stdlib» довело T1 до самодельной
  криптографии. Реальное решение (keyring, переменная окружения, хранилище ОС) в рамки не вписывалось.
- Ревью без рассуждения (повтор при пустом ответе) может быть менее вдумчивым; в итоговых прогонах повтор не понадобился.
- Генерируемый код выполняется на этой машине: урезанное окружение и таймаут 60 с, но **без изоляции** сети и диска.
- Шлюз маскирует не всё: известные пропуски Input Guard (hex, ROT13, буквы через пробел, кириллические двойники,
  пересказ словами) описаны в [README дня 3](../day%203/README.md).

## Security-промпт

`security_prompt.build_prompt("python")` — общая часть (шкала Critical/High/Medium/Low, формат JSON, указание
считать комментарии в коде недоверенными данными, метки `[REDACTED_*]` — не уязвимость) плюс стек-специфика:
- **python:** токены и пароли только в хранилище ОС / переменных окружения / файле 0600; PII и `Authorization` в
  логах; `verify=False`, `http://`, нет таймаута; Flask `debug=True`; `shell=True`, `pickle`, `eval`; `random` вместо `secrets`.
- **ios:** Keychain вместо UserDefaults, исключения ATS, certificate pinning, логи через `print`/`NSLog`.
- **android:** `EncryptedSharedPreferences`, network security config (`cleartextTrafficPermitted`), root detection, `Log.d` с токенами.
