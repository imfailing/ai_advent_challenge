# Advanced / День 3 — Testing: отчёт

## Уровень 1 — код-тесты (агент `tester`, один промпт)
Промпт: «Найди модули сервиса, которые не покрыты тестами, напиши тесты, запусти и убедись, что всё проходит».
Агент построил карту покрытия, нашёл непокрытые `github_repo`, `notify`, `digest` (офлайн) и маршруты `app.py`, и написал 4 файла:

| Файл | Что проверяет |
|---|---|
| `test_github_repo.py` | `parse_repo` (URL/.git/ssh/мусор), `get_commits` (маппинг, кламп `last`, заголовок токена, 404/403/прочие ошибки → RuntimeError по-русски) |
| `test_notify.py` | деградация без токена, payload/URL, обрезка до 4096, ошибки Telegram и сети |
| `test_digest_unit.py` | `_commits_block`, `generate` с подменённым OpenAI (neutral/toxic, температуры, ошибки ключа) |
| `test_app_routes.py` | `/`, `/health`, `/generate` (все ветки ошибок, кламп, токены, 500 от AI), `/publish` |

Результат (проверено мной независимо): 5 файлов PASS (вместе с `test_stats.py`), каждый < 0,4 с, код приложения не изменён,
ruff чистый. Мутационная проверка (из отчёта агента): сломанный `min(last, 100)`, обрезка `[:4000]`, код 500→400 — тесты падают.

Не «с первого запуска»: `test_digest_unit.py` упал на неверном ожидании (двойной пробел в строке «Период» при пустых датах).
Находки кода (зафиксированы в отчёте агента, не исправлялись): `/generate` падает HTML 500 на теле `null`; не-списочный ответ
GitHub → `AttributeError`; сырые английские сообщения сетевых ошибок; Markdown-режим Telegram отвергает непарные `_`/`*`.

## Уровень 2 — UI smoke (агент `smoke-runner`, встроенный браузер MCP)
5 сценариев → **5 PASS / 0 FAIL**, затем после «деплоя» фичи — **6 сценариев → 6 PASS** (см. ниже). 17 скриншотов в `smoke/screenshots/`
(проверены вручную: например `S2_03_result.png` — отрендеренный дайджест, `S6_03_result.png` — таблица статистики).
Проверка шага — по DOM (`#status` + класс, `#out`, `#pub`, `localStorage`), не «на глаз».

| Сценарий | Что проходит |
|---|---|
| S1 | пустая форма → «Укажите репозиторий»; нет ключа → «Укажите ключ DeepSeek», раскрытие «Токены» |
| S2 | токен + репозиторий + снятие rooster → дайджест отрендерен (h1 + 3×h2, списки), «Опубликовать» активна |
| S3 | `ghost/none` → «не найден»; ключ `bad-key` → «AI: … 401» |
| S4 | публикация без токенов → ошибка; с токенами → «✓ Опубликовано» |
| S5 | токены переживают перезагрузку; `localStorage.clear()` → поля пусты |
| S6 (новый) | «📊 Статистика»: пустой repo → ошибка; `octo/demo` → авторы/дни/самый активный день; `ghost/none` → ошибка, блок скрыт |

Если что-то падает: профиль требует указать шаг, «ожидалось/получено», скриншот и предположительное место (файл:функция). В этом
прогоне падений не было, поэтому эта часть профиля на реальной поломке не проверялась.

## Интеграция в flow
- `run_tests.sh` + `.github/workflows/tests.yml` — на каждый PR: ruff и офлайн-тесты (CI-конфиг я не запускал).
- Скилл **`pr-verify`**: что изменилось → код-тесты (`tester` для непокрытого) → smoke-сервер + `smoke-runner` → единый отчёт `reports/<дата>-<тема>.md` с вердиктом.
- Скилл **`post-deploy`** («я задеплоил фичу — обнови сценарии и прогони всё заново»): находит фичу по диффу, дописывает сценарий, прогоняет всё.
  Проверен на реальной фиче: я добавил в UI кнопку «📊 Статистика»; агент сам нашёл её по diff с базой, добавил S6 (3 шага), прогнал 5 PASS код-тестов
  и 6 PASS UI-сценариев и собрал `reports/2026-10-22-stats-button.md`.

## Что больше всего повлияло на качество
1. **Офлайн-заглушки (`smoke_server.py`)** — сценарии детерминированны, не зависят от сети и ключей, ошибки (`ghost/none`, `bad-key`) вызываются по требованию.
2. **Проверка по DOM + скриншот на шаге** — результат шага проверяем и показываем; скриншоты через `html2canvas` → файл (инструмент браузера отдаёт картинки только в чат).
3. **Мутационная проверка в профиле tester** — отличает тесты, которые что-то ловят, от декоративных.
4. **Формат отчёта с «Не проверено»** и обязательная перепроверка артефактов (`ls`) — несколько «заявлено, но не сделано» поймано именно так.
5. **Скиллы как оркестрация** (`pr-verify`, `post-deploy`) — один промпт запускает оба уровня и даёт единый отчёт.

## Оговорки
- Smoke идёт против заглушек, не против реальных GitHub/DeepSeek/Telegram; мобильная вёрстка не проверялась (Claude in Mobile не использовался).
- Скриншоты `html2canvas` — не пиксель-в-пиксель с браузером (возможны мелкие артефакты закрытого `<details>`).
- По одному прогону каждого профиля; исполнитель — general-purpose агент, читающий файл профиля.
