## Пул задач
[TASKS.md](TASKS.md) — 18 задач на сервисе анализа GitHub-репозитория (копия Дня 3): **5 багов** (T01–T05, реальные находки Дня 3),

«сделано» словами; общий критерий для всех: `./run_tests.sh` (ruff + все тесты) зелёный и отдельный коммит `Txx: …`.
Ловушка: T10 (лимит запросов на `/generate`) ломает существующие тесты, которые вызывают `/generate` много раз.

## Как проверялось
- Каждый прогон идёт в отдельной песочнице — своём git-репозитории (`harness/make_sandbox.sh`): проект, правила и профили из корня репозитория,
  `LOOP.md` (инструкция цикла), пул. Ассистенту не показываются скрытые проверки `harness/verify/check.py`.
- **Независимый вердикт** (`harness/verify_run.py`) по истории git: каждый коммит `Txx` разворачивается в чистый каталог → скрытая проверка критерия +
  ruff + все тесты; затем те же проверки на `HEAD` (регрессии). Слова ассистента «сделано» вердиктом не считаются.
- Метрики: **серия подряд** с начала пула (где первый срыв), **максимальная серия подряд**, **% с первого раза** (один коммит и критерий выполнен),
  время (по меткам коммитов и по длительности агента), доля подтверждённых задач.

## Локальная модель (qwen3:8b): где и почему ломается
Выбор модели: в Дне 4 она лучше всех работала с инструментами. Тот же пул, та же песочница, те же правила (короткие), новая беседа на каждую задачу, 20 шагов и 4 мин на задачу.

**Прогон A (протокол v1):** 0/18. Закоммитила 3 задачи (T12, T14, T17) — все неверные; сообщение коммита T17 вообще про другое. Одна из ранних правок
**сломала `test_github_repo.py`**, а рабочее дерево не откатывалось — «красное» состояние заразило всё остальное (каскад).
Диагностика на T01/T09: модель **не вносит ни одной правки** — запускает уже зелёные тесты, пробует `commit` (коммитить нечего), повторяет 20 раз,
а на T01 заключает «проблема уже решена», не воспроизведя баг.

**Доработка протокола → v2** (правки по найденным падениям):
1. шаг «сначала докажи, что критерий НЕ выполнен» (проверочный код через `run_python`) — зелёные существующие тесты не доказывают решённость;
2. `commit` отклоняется, если файлы не менялись или после последней правки тесты не зелёные;
3. шлюз цикла: задача засчитана только при зелёном `run_tests`, иначе откат рабочего дерева/коммита к последнему хорошему состоянию (нет каскада);
4. образец последовательности для багов, правило «`old` копируй точно из `read_file`».

**Прогон B (протокол v2):** 2/18 подтверждено (T16, T18 — документация), `HEAD` теперь чистый (откаты сработали), но кодовые задачи 0 из 15.
Причины (по трассировке):
- **зацикливание на неверном способе проверки**: T01 — 15 одинаковых вызовов `requests.post('http://localhost:5000/…')` на несуществующий сервер (хотя профиль велит `app.test_client()`);
- **разрушительные правки**: T06 — `write_file` затёр `activity.py` пятью строками;
- **выдумывание вместо чтения**: T12 — `prompts.py` написан «по памяти» с вымышленным текстом промптов, а `digest.py` не прочитан; **все существующие тесты остались зелёными** —
  значит, тесты не проверяют содержимое промптов, и беспроверочный коммит прошёл бы шлюз (поймала только скрытая проверка критерия);
- **разрушительная «успешная» правка**: T18 формально выполнила критерий (раздел «Ограничения» есть), но заменила README почти целиком (+7/−131 строк) и стёрла примеры curl из T16 — на `HEAD` T16 уже не выполняется. Шлюз «зелёные тесты» такое не видит: регрессию в документации ловит только проверка критерия на `HEAD`.
Класс задач, который тянет локальная 8B: **шаблонные правки документации**. Баги, фичи, рефакторинги, тесты — нет.

## Сравнение: облако против локальной
| Критерий | Облако | Локальная qwen3:8b |
|---|---|---|
| Сколько подряд без паузы | 18 из 18 (весь пул), дважды | 0 (A), 0 серии с начала / макс. 1 (B) |
| С первого раза | 100 % | 0–11 % |
| Время на пул | ~5 мин | 21–32 мин и почти без результата |
| Самоконтроль | воспроизводит, проверяет откатом, правит тесты, ловит ловушки | не меняет файлы, зацикливается, выдумывает, затирает файлы |
| Честность отчёта | отчитывается верно (подтверждено), мелкие неточности времени/логов | заявляет «тесты прошли / уже решено» без проверки |
| Работа без сети, приватность | нет | да |
**Вывод:** в режиме execution loop (много задач подряд без вмешательства) облачный ассистент достаточен для всего пула; локальная 8B без вмешательства
не держится даже на первой задаче, а подсказки-протокол помогают лишь частично (шлюз и откат спасают репозиторий от каскада, но не делают модель способной решать код).
Рекомендация: локально — автокомплит и разовые правки с человеком в цикле; execution loop — облако, со шлюзом «зелёные тесты + откат» как страховкой в любом случае.
