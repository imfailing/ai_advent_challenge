# Пул задач (трекер) — сервис анализа GitHub-репозитория

Каждая задача: тип, описание, критерий «сделано». Статус: `todo` → `done` / `failed` / `skipped`.
Ассистент берёт первую задачу со статусом `todo`, выполняет, коммитит `Txx: …`, меняет статус и идёт дальше.
Общий критерий для ВСЕХ задач: `./run_tests.sh` (ruff + все тесты) зелёный, изменение закоммичено отдельным коммитом.

## T01 [bug] `null` в теле запроса даёт HTML 500
`POST /generate` с телом `null` (Content-Type: application/json) падает с 500 и HTML вместо JSON.
**Сделано, когда:** `/generate`, `/stats`, `/publish` на тело `null` отвечают JSON `{"error": …}` с кодом 400.
status: todo

## T02 [bug] Ответ GitHub не списком
Если GitHub вернул не список коммитов (например, `{"message": "Bad credentials"}` с кодом 200), `get_commits` падает с непонятным `AttributeError`.
**Сделано, когда:** в этом случае `get_commits` бросает `RuntimeError` с понятным русским сообщением, упоминающим GitHub.
status: todo

## T03 [bug] Сетевые ошибки GitHub не переводятся
Сбой сети (`URLError`) или таймаут при запросе к GitHub уходят пользователю сырым английским исключением.
**Сделано, когда:** `get_commits` на `urllib.error.URLError` и на `TimeoutError` бросает `RuntimeError` с русским сообщением вида «Не удалось связаться с GitHub: …».
status: todo

## T04 [bug] Пустые даты ломают заголовок дайджеста
Если у коммитов нет дат, заголовок дайджеста содержит «_Период:  · коммитов: N_» (пустой период, двойной пробел).
**Сделано, когда:** при отсутствии дат вместо периода пишется «нет дат», двойных пробелов в строке периода нет.
status: todo

## T05 [bug] Telegram отвергает дайджест из-за Markdown
Дайджест с непарными `_`/`*` Telegram отклоняет (HTTP 400 «can't parse entities»), публикация падает.
**Сделано, когда:** при HTTP 400 с «can't parse entities» `send_telegram` повторяет отправку без `parse_mode` и возвращает `status: "sent"`; повторный запрос не содержит `parse_mode`.
status: todo
