# День 9. Дистилляция: большая модель учит маленькую

**Задача:** письмо клиента на русском → JSON из семи полей (`category`, `sentiment`, `product`, `order_id`,
`amount_rub`, `action_required`, `summary` ≤ 15 слов).
**Учитель:** DeepSeek `deepseek-v4-flash` (API). **Ученик:** Qwen2.5-1.5B-Instruct + LoRA (r=16, как в днях 6–8).
**Тест:** 80 писем, не входят в обучение (макс. словесное сходство с обучающими 0,52). **Обучение:** 540 ответов учителя.

## Итог одной таблицей

| | Ученик до | Ученик после (слитый адаптер) | Учитель (API) |
|---|---|---|---|
| Валидный JSON по схеме | 72,5% | **100%** | 98,8% |
| Все 6 полей верны | 26,3% | **86,3%** | 88,7% |
| category / product / order_id / amount_rub / action_required | 72,5 / 82,5 / 80 / 97,5 / 92,5% | **100% по всем пяти** | 100 / 96,3 / 100 / 100 / 100% |
| sentiment | 80% | 86,3% | 91,2% |
| Задержка, среднее / p95 | 3,5 / 4,2 с | 3,0 / 3,5 с | **1,2 / 1,4 с** |
| Стоимость запроса* | ≈ $0,00001 | ≈ **$0,0000084** | $0,000085 |

\* Учитель — токены × тариф ($0,14 / $0,28 за 1 млн токенов вход/выход; цены найдены поиском, на официальной
странице подтвердить не удалось). Ученик — **только электричество**: допущено 100 Вт и $0,10/кВт·ч, мощность не
измерялась. Железо, амортизация и обслуживание сервера не учтены.

**Вывод:** на узкой задаче с жёсткой схемой ученик почти догнал учителя (86,3% против 88,7%, при n=80 разница
в 2 письма — в пределах шума) и примерно в 10 раз дешевле по энергии. Но он **медленнее** API (в 2,5 раза) и всё ещё
уступает по тональности.

## Что делалось

1. **Данные.** Учитель писал письма под случайно выбранные «задания» (категория, тональность, продукт, номер
   заказа, сумма, стиль письма). Номер заказа, сумма и продукт заданы заранее, поэтому для них эталон объективен.
   Дубли (Жаккар ≥ 0,6) и письма, не совпавшие с заданием, удаляются. 795 писем → 100 тест / 695 пул.
2. **Первая постановка не сработала.** Сначала в схеме было поле `priority`. Эталон по нему задавался при
   генерации, и учитель совпал с ним всего в 30% (после явных правил — 44%): в спорных письмах правым был учитель
   (двойное списание он ставил «high» — это следует из правила про деньги). Шумит эталон, не модель, поэтому
   поле заменено на объективное `amount_rub` (`notes/priority_attempt.md`). Тональность после уточнения правил — 86%.
3. **Ручная проверка теста.** Из 100 тестовых писем учитель расходился с эталоном в 34. Каждое прочитано:
   5 эталонов исправлены (тональность «негативная» при явном раздражении; продукт не назван в тексте), 20
   неоднозначных удалены (смешанные темы, граница «нейтрально/негативно»), настоящие ошибки учителя оставлены
   (`review_test.py`). Остался тест из **80** писем. Тест после этого чище реального потока — см. ограничения.
4. **Ответы учителя на 695 письмах пула.** Фильтр: валидный JSON по схеме, `summary` ≤ 15 слов, объективные поля
   (`order_id`, `amount_rub`, `product`, `category`, `action_required`) совпадают с заданием. Отсеяно 95 из 695
   (14%): category 48, action_required 23, product 15, summary 8, order_id 1. Тональность не фильтровалась.
   Итог: 540 в обучение + 60 в valid. Тестовые письма в обучение не попадали.
5. **Обучение.** 3 эпохи, batch 8, lr 2e-4, 204 шага, **864 с**, пик памяти 39 ГБ. Valid loss 0,244 → 0,163,
   к концу плато (0,163–0,164), признаков переобучения нет.

## Где ученик уже заменяет учителя, а где ошибается

- **Заменяет:** `category`, `action_required`, `order_id`, `amount_rub`, `product` — по 100% на тесте
  (у учителя `product` 96,3%: он трижды додумал «Облачко Курьер», когда продукт не назван). Формат JSON — 100%,
  у базовой модели 72,5%.
- **Ошибается:** `sentiment`. Из 12 ошибок ученика (версия без слияния адаптера) 6 — только его (почти всегда «негативная» вместо «нейтральной»
  для делового письма о проблеме), в 6 ошибся и учитель (граница нейтрально/негативно субъективна), в 1 — только учитель.
- **Не оценено автоматически:** качество `summary`. Проверялась лишь длина. Выборочно видны огрехи ученика
  («скачать закрытие» вместо «закрывающие документы»), у учителя формулировки ровнее.

## Скорость и цена: что на самом деле

- Ученик **медленнее API**: 3,0 с против 1,2 с на запрос (batch=1, жадная генерация HF, встроенная графика
  Radeon 8060S без оптимизированного сервера). Неслитый адаптер добавляет ещё ~2 с (5,3 с): на каждом шаге
  генерации считаются два дополнительных матричных умножения.
- Экономия по энергии ≈ 10× ($0,0000084 против $0,000085), но в абсолютных цифрах API так дёшев, что
  без учёта железа выигрыша почти нет. Построение данных: учитель на разметку пула израсходовал ≈ $0,067, на
  генерацию писем ≈ $0,055 (последняя итерация; две первые, отброшенные, стоили сопоставимо). При экономии ≈ $0,000076
  на запрос только разметка окупилась бы примерно за 900 запросов, с генерацией — за 1600. Обучение: 864 с ≈ 0,024 кВт·ч.
- Оправдание ученика — не цена токенов, а то, чего API не даёт: данные не уходят наружу, нет лимитов и
  зависимости от сети, предсказуемая задержка при собственном GPU, жёсткий формат.

## Ограничения (что НЕ проверено)

- Тест — 80 писем, один seed, один запуск обучения: ±4–5 п.п. — норма. Разрыв 86,3 / 88,7% статистически не значим.
- Письма синтетические и написаны той же моделью, что и учитель (одна «семья»), поэтому учитель, возможно,
  выглядит лучше, а ученик — легче, чем на реальной почте. На реальных письмах не проверялось.
- Тест очищен от неоднозначных писем (20 из 100). На неочищенных данных точность по тональности и категории
  ниже у обеих моделей (до чистки учитель совпадал с эталоном в 66% писем целиком).
- Из-за слияния адаптера в bf16 результат отличается от неслитого на одно письмо (85% → 86,3%) — шум вычислений.
- Стоимость ученика — допущение по мощности (не измерена), без железа и труда; цена учителя — по данным
  сторонних сайтов. Только один размер ученика (1,5B), без квантования и без быстрых серверов (vLLM и т. п.).
- Полнота `summary` и «сомнительные» примеры внутри 540 (где учитель мог ошибиться в тональности) не проверялись:
  на них фильтр не действует.
- Не проверено, сколько примеров нужно: зависимость качества от размера обучающего набора не снималась.
