# День 10. Тюненая модель в проде

**Что сделано.** Адаптер дня 7 (классификатор типа коммита, Qwen2.5-1.5B + LoRA) слит с базой, сконвертирован в GGUF,
проквантован, запущен под `llama-server` и подключён к сервису недели 8 (дайджест репозитория). Сервис —
копия `week 8/day 1` в `week 9/day 5/` + новый эндпоинт `POST /classify` (тип каждого коммита), реестр версий моделей
и переключение **без перезапуска**. Раньше в сервисе стояла только облачная модель DeepSeek; она осталась
запасным вариантом.

Для сравнения, день 7 на HF-версии: тюн 69,2%, база с промптом 26,9%. Конвертация в GGUF точность не ухудшила
(70,2% — разница в одно письмо). Прямого замера HF-версии на этой задаче нет (в дне 9 HF-ученик отвечал за 3,0 с, но задача другая, с ответом ≈ 80 токенов вместо ≈ 7).

**Выбор кванта.** Q8_0 не теряет качество относительно f16 и вдвое меньше; Q4_K_M ещё легче и быстрее, но теряет
4,8 п.п. (в повторном прогоне проверки 66,3–67,3%: llama-server на GPU не бит-в-бит детерминирован, шум ±1–2 коммита).
Чтобы такое не пропускалось, проверка перед выкаткой сравнивает кандидата с активной версией (допуск 2 п.п.): Q4 с
`--baseline tuned-v1` проверку не проходит.

Ограничения замеров: время загрузки 0,8 с — при файле в кэше ОС, холодную загрузку (диск) не мерил; «память GPU» — VRAM+GTT
по sysfs, у встроенной графики веса лежат в общей памяти, цифра включает KV-кэш при `-c 4096`.

## 2. Сервис: что подключено и как переключается

- `model_registry.py` — каталог версий (`registry/models.json`: id, URL, режим промпта, sha256 файла), активная
  версия и стек отката (`registry/state.json`, атомарная запись). Сервис читает файл на каждый запрос.
- `POST /models/activate {id}` — включает версию, **только** если она прошла проверку и её `llama-server` отвечает.
  `POST /models/rollback` — возвращает предыдущую. `GET /models` — список, активная, онлайн ли, проверена ли.
- `POST /classify {repo|message, model?}` — типы коммитов активной (или указанной) моделью; ответ — по каждому
  коммиту, распределение `by_type`, средняя задержка. Ошибки — JSON `{error}` с 400/500, как у соседних маршрутов.
- Проверка перед выкаткой (`scripts/verify_model.py`): `data/eval.jsonl` (104 коммита, не в обучении), пороги
  accuracy ≥ 0,60, строгий JSON ≥ 0,95, не хуже активной более чем на 2 п.п.

Прогон на живом сервисе: `base-qwen-q8` включить **нельзя** (accuracy 27,9% < 60%) — сервис ответил 400;
`tuned-v1` проверку прошёл (70,2%) и включён; `rollback` вернул DeepSeek, повторная активация вернула тюн.
Переключение занимает 2–14 мс, процесс сервиса при этом не перезапускался.

## 3. Было и стало (то, что стояло раньше: DeepSeek, `deepseek-v4-flash`)

| | DeepSeek (облако) | Тюн Q8 (локально) |
|---|---|---|
| Accuracy на 104 коммитах | 66,3% | **70,2%** |
| Строгий JSON | 100% | 100% |
| Задержка на запрос через сервис | 1,04–1,08 с | **0,10–0,16 с** |
| 30 коммитов подряд | ≈ 32 с | ≈ 3–5 с |
| Стоимость запроса | ≈ $0,000044 (303 токена промпта) | ≈ $0,00000026 (только энергия, допущение 100 Вт и $0,10/кВт·ч) |
| Данные уходят наружу | да | нет |

На 104 коммитах тюн не хуже облака (70,2 против 66,3% — разница в 4 коммита, при n=104 и шуме ±1–2 коммита
это не значимый перевес). Эталон — тип из префикса коммита (как в дне 7), он сам шумный.

**На реальных репозиториях** (`pallets/flask`, `psf/requests`, этот репозиторий, по 30 коммитов; эталона нет,
считается согласие моделей):

| | flask | requests | наш репо |
|---|---|---|---|
| тюн ~ DeepSeek | 73% | 77% | 57% |
| база+промпт ~ DeepSeek | 77% | 67% | 60% |
| тюн ~ база+промпт | 57% | 83% | 53% |

Согласие тюна с DeepSeek в среднем 69%, у базы с промптом — 68%: **на живых коммитах превосходство тюна над базой
не видно** (в дне 7 оно было большим на 104 коммитах с эталоном 70% против 28%). Расхождения разбирались выборочно:
тюн ставит `docs`/`chore` у коротких коммитов «fix typing», «fix dev», где облако и база говорят `fix`. Кто прав на
живых данных без ручной разметки сказать нельзя; эталона на живых коммитах нет.

## 4. Что НЕ проверено / ограничения

- Качество на живых коммитах измерено только как согласие моделей, без ручной разметки.
- Нет нагрузочного теста (параллельные запросы, `-np`), только последовательные запросы по одному.
- Холодная загрузка с диска; память при длинных входах (`-c 4096`); квантования, кроме Q8_0 и Q4_K_M.
- `state.json` локален для одного процесса; sha256 в реестре записан, но не сверяется автоматически.
- Цена DeepSeek — по ценам из поиска ($0,14 / $0,28 за 1 млн токенов), на официальной странице не подтверждена;
  цена тюна — только электричество, без железа.
- В сервис не добавлен UI для переключения (только API), Docker-образ дня не пересобирался: GGUF-серверы вынесены
  на отдельный хост и подключаются через туннель.
